# 备份、导入与恢复

JSON 是推荐的无损、可移植备份。备份包含邮箱/手机号及关联关系，属于私密文件；不要上传公开仓库或分享链接。导出不设 500 条截断，导入限 1 MiB、500 个帐号（JSON 另限平台/分类各 1000）。超过恢复上限的完整备份应保留，并由维护者在隔离环境扩展验证后的上限或使用 D1 SQL 恢复；不要手工裁剪 ID 关联后贸然恢复。

## JSON v1

根结构：`schemaVersion:1`、`exportedAt`（UTC ISO）、`platforms`、`categories`、`accounts`。标签保存在每个帐号的 `tags` 字符串数组。参考 [可恢复示例](backup-example.json)（虚构资料，不会自动导入）。空平台/分类也导出；不包含 Secret、会话、环境变量或迁移表。

恢复步骤：

1. 设置 → 数据备份 → 先导出当前 JSON。
2. 选择可信 JSON 文件，点“校验并预览”，查看平台/分类/帐号数量、重复候选数和将替换的现有数据量。
3. 点击“确认恢复并替换”，再次明确确认。全量替换，不合并。
4. 成功后所有视图刷新；核对数量和随机记录。失败时不自动重试，先检查当前数据。

后端在预览和提交分别重新校验版本、类型、ID 唯一性、名称去重、时间、外键关联、必填和字段长度。任何错误拒绝写入。所有 DELETE/INSERT 在同一个 D1 `batch()` 事务中执行，失败整体回滚，保留 sessions 和 D1 migrations 表。预览不是预留数据库快照，确认前避免在其他设备修改数据。

## CSV 八列

[空模板](account-import-template.csv)；UTF-8，允许 BOM，固定表头及顺序：

```csv
所属平台,登录帐号,登录网址,绑定邮箱,绑定手机号,帐号备注,自定义分类,标签
GitHub,,,person@example.com,+8613800000000,"多行备注第一行
第二行，包含逗号与""双引号""",开发工具,"[""个人"",""工作""]"
```

由 Papa Parse 解析逗号、引号和多行内容；手机号不转换数字。标签列为空或 JSON 字符串数组，不使用逗号拆标签。平台/分类按名称解析，不存在则创建。空分类是未分类。导入为追加，永不覆盖已有帐号；默认跳过可能重复项，可勾选保留。预览显示有效数、写入数、重复候选和错误记录行号（含表头；多行单元格算一条记录）。存在任何错误时整个文件不写入；修正后重新预览。每次最多 500 条，建议大文件按完整记录拆分，不要截断多行单元格。

CSV 不保留 ID、时间、空平台/空分类或网址继承语义。导出网址为当时有效网址，导入后作为帐号覆盖值。Excel 可能把 `00123`、`+86…` 或长数字自动改写；请以文本导入，不要将 CSV 作为唯一备份。

公式注入防护：导出字段若以 `= + - @`（可在前面有空白）或制表符/换行开头，前置单引号。CSV 重新导入时不会自动去掉这个单引号，以免把本来存在的单引号误删。因此 CSV 交换在这些文本上不是无损；需要精确保留 `+` 手机号等值请使用 JSON。帐号文本字段本身仍按需求 trim 首尾空白。

## D1 运维备份

应用 JSON 不含会话，首选此格式。D1 SQL export 是管理员备用操作，文件可能包含会话查找值和所有私人信息，应保存在受限目录：

```sh
npx wrangler d1 export DB --remote --output=./backups/account-space.sql
```

先创建 `backups` 文件夹（Windows/macOS/Linux 文件管理器均可）。从 SQL 恢复整个数据库属于破坏性运维操作，先在独立测试数据库验证，遵循 Cloudflare D1 import 文档；恢复后通过 Dashboard 改为新的随机管理员密码以撤销旧会话，并核对数据。若仅需撤销全部会话，可由管理员执行：

```sh
npx wrangler d1 execute DB --remote --command="DELETE FROM sessions"
```

不要把本页的远程命令加入普通本地启动/安装脚本。Time Travel Free 通常保留 7 天，不能代替长期独立备份；实际能力以 Cloudflare 当前方案为准。
